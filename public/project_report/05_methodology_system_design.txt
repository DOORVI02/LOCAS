4. METHODOLOGY AND SYSTEM DESIGN

4.1 Methodology
The project followed the **Iterative Waterfall** model, which allows for revisiting previous phases when defects are discovered. The phases included:
1.  **Requirement Analysis:** Identifying entities (Books, Users, Transactions), attributes, and their relationships.
2.  **Database Design:** Creating the ER Diagram and normalizing schemas to 3NF.
3.  **Application Design:** Structuring the Python application using the MVC (Model-View-Controller) pattern to separate logic from UI.
4.  **Implementation:** Coding the modules (Auth, Inventory, Circulation) and integrating with the MySQL database.
5.  **Testing:** Performing Unit testing of database constraints and Integration testing of GUI workflows.

4.2 System Architecture
LOCAS uses a **2-Tier Client-Server Architecture**:
*   **Client Tier:** The Python/PyQt6 application running on the local desktop. It handles user input, validation, and presentation logic.
*   **Data Tier:** The MySQL Database Server handling data storage, integrity constraints, and query execution.

4.3 Database Design (ER Diagram)
The database serves as the backbone of the system.
*   **Users:** Stores login credentials and profile info. Linked to Roles.
*   **Books:** Stores metadata (ISBN, Title, Author).
*   **BookCopies:** Represents physical items identifiable by barcode. Linked to Books.
*   **Transactions:** Records the event of issuing/returning. Links Users and BookCopies.
*   **Fines:** Records monetary penalties associated with Transactions.

4.5 Data Dictionary
A brief description of key tables:
*   **users**: The central table for authentication. `role_id` determines access level. `is_active` acts as a soft-delete mechanism.
*   **books**: Contains the static data about a publication. `total_copies` and `available_copies` are denormalized fields updated via triggers/application logic for fast read performance.
*   **transactions**: The historical log of library usage. `status` tracks if the loop is closed (Returned) or open (Active/Overdue).
