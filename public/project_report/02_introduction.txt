1. INTRODUCTION

1.1 Background
Libraries are the intellectual heart of any educational institution, serving as the primary repository of knowledge, research, and resources effectively essential for academic growth. In the current digital era, the efficiency of a library is defined not just by its collection of books, but by how easily those resources can be accessed by students and faculty. In many traditional setups, specifically in smaller colleges or departments, library management still relies heavily on manual processes—using physical cards, paper registers, and manual filing systems to track books and borrowers. As the volume of books grows and the number of students increases, these manual methods become rapidly inefficient, prone to human error, and time-consuming. The transition from a manual to a digital system is not merely a convenience but a necessity for maintaining operational integrity.

1.2 Overview of the Project
LOCAS (Library for College Administration System) is a comprehensive desktop-based application designed to modernize these operations. It leverages the power of a Relational Database Management System (RDBMS) to ensure data integrity, quick retrieval, and efficient management of library resources. The system is tailored effectively for the specific needs of UTD-CSVTU Bhilai, focusing on the interactions between books, students, and librarians. Unlike generic software, LOCAS is built with the specific semester-based workflow of the college in mind.

1.3 Objectives
The primary objectives of this project are multi-faceted:
*   To design a normalized database schema that efficiently stores information about books, copies, users, roles, transactions, and fines, reducing data redundancy.
*   To develop a user-friendly Graphical User Interface (GUI) that allows librarians to easily issue and return books with minimal training.
*   To implement robust business logic for automatic fine calculation, rule enforcement (e.g., maximum borrow limits), and late return processing.
*   To provide data security through hashed authentication and Role-Based Access Control (RBAC) authorization mechanisms.
*   To generate useful, real-time reports for administration regarding book utilization, overdue stats, and inventory status to aid in decision making.

1.4 Scope and Constraints
**Scope:**
The scope of LOCAS currently covers:
*   **Inventory Management:** Complete lifecycle management (Add, Update, Remove) of Books and specific Book Copies.
*   **User Administration:** Registration and profile management for Students and Librarians.
*   **Circulation Control:** Handling Issue/Return transactions with precise date tracking and status updates.
*   **Financial Management:** Automated calculation and recording of fines for late returns.
*   **Search Engine:** A dynamic search feature allowing lookups by Title, Author, Category, or ISBN.
*   **Dashboard Analytics:** Visualization of key metrics like "Total Books," "Pending Fines," and "books due today."

**Constraints:**
*   The system is currently designed for a single-branch library environment (Intranet).
*   It does not currently support inter-library loan requests.
*   The system requires a desktop environment (Windows/macOS/Linux) to run the client application.

1.5 Technologies Used
*   **Programming Language:** Python 3.12 (Selected for its rapid development capabilities and rich library ecosystem).
*   **GUI Framework:** PyQt6 (Qt for Python) - Provides native-looking, high-performance UI components.
*   **Database:** MySQL 8.0 - A reliable, industrial-strength RDBMS for storing structured data.
*   **Database Connector:** mysql-connector-python - For efficient Python-to-SQL communication.
*   **Architecture:** MVC (Model-View-Controller) pattern - To ensure separation of concerns and maintainability.
